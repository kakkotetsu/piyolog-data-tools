# 育児記録の分析とMarkdownレポート

`analyze_piyolog.py` は原本JSONファイル群を読み取り、プログラムで計算した集計値と、外部LLMによる振り返りをローカルにMarkdownファイルで保存します。

## 1. 環境設定

Python 3.10以降で動作します。Python 3.10ではTOMLを読むための`tomli`だけを追加します。3.11以降は標準ライブラリを使います。

```bash
.venv/bin/python -m pip install -r requirements-advisor.txt
cp config/advisor.example.toml advisor.toml
chmod 600 advisor.toml
```

`advisor.toml` の `child.birth_date` を実際の日付へ変更します。生年月日は月齢計算にだけ使い、LLMには満月齢とその基準日を渡します。月齢は分析期間の最終日（終了日の前日）時点です。

早産で修正月齢を使う場合は、`child.corrected_birth_date` に出産予定日を設定できます。未設定なら実月齢だけを使います。

`analysis.focus` は相談したいこと、`analysis.context` は体調や医師からの指示などの補足です。**両方ともLLMへ送信されます。** 必要な情報に絞り、氏名などは記載しないでください。

## 2. 外部通信なしで確認(dry-run)

```bash
.venv/bin/python analyze_piyolog.py --dry-run
```

APIキー・接続先・モデルが未設定でも利用できます。モデル未設定の場合、送信予定JSONにはプレビュー専用の仮のモデル名が入り、そのままAPIに送ることはできません。

出力例（実行ごとに別のディレクトリを作成します）:

```text
data/advisor/reports/<生成日時>-preview-<識別子>/
├── metrics.json    # プログラムが計算した結果
├── request.json    # 送信予定の本文。認証ヘッダーは含まない
└── report.md       # 集計表。AIを実行していないことを明記
```

標準出力には保存先だけを表示し、育児記録や生成文は表示しません。レポートやJSONにも個人情報が含まれるため、出力ディレクトリは所有者のみアクセス可能、ファイルは所有者のみ読み書き可能にします。`advisor.toml`と`data/advisor/`はGit管理対象外です。別の設定名・出力先を指定する場合は、その保存先もGit管理から除外してください。

## 3. LLM設定

既存の`.env`に設定します。`<id>`はCodexの`config.toml`の`model_provider`で選択した値です。

| `.env`項目 | Codex `config.toml`の項目 |
| --- | --- |
| `ADVISOR_LLM_PROVIDER` | `model_providers.<id>.wire_api`（`responses`） |
| `ADVISOR_LLM_BASE_URL` | `model_providers.<id>.base_url` |
| `ADVISOR_LLM_MODEL` | `model` |
| `ADVISOR_LLM_API_KEY_ENV` | `model_providers.<id>.env_key`（環境変数名） |
| `ADVISOR_LLM_API_KEY` | `env_key`が指す環境変数の値を直接設定する場合に使用 |

APIキーは間接指定と直接指定のどちらかを使います。[Codex設定リファレンス](https://developers.openai.com/codex/config-reference/)

## 4. 送信範囲を設定してレポートを生成

初期設定の送信内容は、集計値、対象期間、取得状況、満月齢、相談したいこと、補足、固定の参考資料だけです。

| 設定 | 有効にしたとき追加される情報 |
| --- | --- |
| `privacy.send_event_details` | 最新版の個別記録の時刻・既知の種類・対応する数値項目。IDや名前などの任意項目は除外 |
| `privacy.send_memos` | 最新版の対象記録のメモ本文と、その種類・時刻。自由記述に含まれる個人情報は自動匿名化しない |

二つの設定は独立しています。メモの設定が無効なときは、食材抽出や要約を通じたメモ内容の送信も行いません。送信範囲を変えたら再度ドライランで確認してください。

`request.json`をローカルで確認し、その情報の外部送信を許可する場合に、`advisor.toml`を次のように設定します。

```toml
[privacy]
allow_external_llm = true
send_event_details = false
send_memos = false
```

集計値も育児に関する個人情報です。リポジトリのデータ保全ルールに従い、実データの送信を許可した運用でのみ有効にしてください。実装・テストのために実データを送る必要はありません。

```bash
.venv/bin/python analyze_piyolog.py
```

結果は`data/advisor/reports/<生成日時>-report-<識別子>/`に保存されます。同じ日に再実行しても前の結果は上書きしません。数値の集計表はプログラムが直接生成し、AIによる解釈・提案と分けて表示します。

`request.json`は実際に送った本文と同じ内容です。APIキーは保存しません。通信失敗、拒否、トークン上限による途中終了、空の回答などではエラー終了し、完成扱いの`report.md`は作りません。事前保存した`metrics.json`と`request.json`は残ります。再実行すると新しいリクエストになり、料金が発生する場合があります。

`llm.max_output_tokens`は推論と回答を合わせた上限です。途中終了する場合は上限を調整してください。`llm.reasoning_effort`は任意で、使用できる値はモデルとルーターによります。自動的なモデル変更や高額モデルへのフォールバックはありません。

## 対象期間と集計方法

```bash
.venv/bin/python analyze_piyolog.py --days 14 --end-date 2026-09-30 --dry-run
```

この例は日本時間の9月16日0時から9月30日0時まで（9月30日は含まない）を分析します。終了日を省略すると設定したタイムゾーンの今日0時になり、未完了の今日を含めません。取得が止まっていても、期間を自動で過去へずらしません。日数は1〜90日です。

- 原本全体からイベントごとの最新版を選んでから、対象期間へ絞ります。日時や種類の訂正を反映します。
- `range`の和集合で取得範囲を確認します。フィード生成時刻・現在時刻より先は取得済みとして扱いません。
- 回数の日平均は取得範囲が一日分そろった日だけで計算します。ただし、記録の入力漏れがない保証にはなりません。記録ゼロは実際の行動ゼロと断定できません。
- 睡眠は連続した取得範囲内の就寝・起床の対から推定します。同種の連続、同時刻の競合、取得の空白、最後の未完了区間は不明にします。睡眠・覚醒の両方を一日全体で推定できる日のみ、総睡眠時間の平均を出します。
- 夜間指標は20時〜翌8時の全体を取得でき、睡眠・覚醒が推定できる夜だけを対象とします。これは集計上の時間帯で、夜間授乳を減らす判断基準ではありません。
- 前半と後半の比較には各期間の対象日数を併記します。奇数日なら後半が一日長くなります。観測日がなければ平均は不明です。
- 授乳時間から母乳量は推定しません。ミルク量は対応する単位ごとに記録値を集計し、必要量の充足を断定しません。
- 原本に残るイベントの削除は検出できません。内容や時刻が訂正されていても、訂正後のフィードを取得できなければ反映できません。

個別イベントを送らなくても、食事時間帯、授乳時間、睡眠の範囲、夜間の記録などの集計を分析できます。メモ送信が無効なら、食材や食べた量の自由記述を使った評価はできません。

初版の参考資料は[AASMの睡眠時間に関する公開指針](https://aasm.org/advocacy/position-statements/child-sleep-duration-health-advisory/)の該当部分です。参考資料を自動検索する機能はありません。入力した資料にない月齢別の数値目標や出典を作らないように指示しますが、AIの文章の正確性を保証するものではありません。診断・投薬・断乳の指示を目的とするツールではなく、必要に応じて健診や医療者への相談材料として使ってください。

## その他の引数と検証

`--config`、`--env-file`、`--data-dir`、`--output-dir`で保存先などを変更できます。`--output-dir`に原本ディレクトリやその配下を指定することはできません。

```bash
.venv/bin/python analyze_piyolog.py --help
.venv/bin/python -m unittest discover -s tests -v
```

分析テストは一時ディレクトリの合成データと模擬API応答だけを使います。実フィード、実APIキー、実LLMへの接続は不要です。

## 実装前のGitチェックポイント

`before-advisor-20260930` は分析機能を追加する前のコミット`0e406c8`を指します。差分の比較や、別のworktreeで以前の版を確認するために使えます。

```bash
git diff before-advisor-20260930
```

チェックポイントが復元するのはGit管理しているコードです。原本、`.env`、個人設定、生成レポートやvenvは含まれません。
